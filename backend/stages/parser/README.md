# Блок 3: Парсинг PDF файлов IMT

## Описание

Этот блок отвечает за извлечение структурированных данных из PDF файлов научных статей журнала IMT. Парсер автоматически извлекает заголовки, авторов, аннотации, ключевые слова, УДК, основной текст статей, а также сопоставляет статьи с тематическими разделами из содержания.

Блок состоит из трех частей:
- **parser_part1.py** — обработка текста и парсинг УДК
- **parser_part2.py** — извлечение тематики из содержания
- **parser_part3.py** — сопоставление статей с темами и главный парсер

## Основные классы и функции

### parser_part1.py

#### Класс `TextProcessor`

Класс для обработки и очистки текста научных статей.

##### `tokenize_for_lda(text) -> List[str]`

Токенизация и лемматизация текста для LDA моделирования.

**Параметры:**
- `text` (str): Исходный текст статьи

**Возвращает:**
- Список лемматизированных токенов (только существительные и прилагательные длиной >2 символов)

**Что делает:**
- Убирает переносы слов
- Оставляет только кириллические символы
- Лемматизирует слова с помощью `pymorphy3`
- Фильтрует части речи (оставляет NOUN и ADJF)
- Удаляет стоп-слова (базовые + академические)

---

##### `normalize_text(text: str) -> str`

Нормализация текста — удаление лишних пробелов и переносов.

**Что делает:**
- Склеивает слова, разорванные переносом строки
- Заменяет переносы строк на пробелы
- Схлопывает множественные пробелы

---

##### `clean_main_text(text: str) -> str`

Глубокая очистка основного текста статьи от шума.

**Что делает:**
- Удаляет приватные символы Unicode
- Удаляет строки с номерами страниц
- Удаляет специальные символы (кроме базовой пунктуации)
- Нормализует пробелы

---

##### `cut_references_tail(text: str) -> str`

Обрезает список литературы в конце статьи.

**Что делает:**
- Ищет маркеры начала списка литературы («СПИСОК ЛИТЕРАТУРЫ», «Литература», «Библиография» и др.)
- Ищет последовательность из 3+ нумерованных библиографических ссылок в конце текста
- Обрезает текст по найденной позиции

---

#### Класс `UDCParser`

Класс для работы с УДК (Универсальная десятичная классификация).

##### `parse_udc(raw: str) -> str`

Извлекает первые цифры из строки УДК.

**Параметры:**
- `raw` (str): Исходная строка УДК (например, "004.8+519.7")

**Возвращает:**
- Первые цифры УДК (например, "004") или "N/A"

**Пример:**
```python
UDCParser.parse_udc("004.8+519.7")  # "004"
UDCParser.parse_udc("N/A")            # "N/A"
```

---

#### Функция `build_text_for_embedding(title, annotation, keywords, main_text) -> str`

Строит полный текст для создания эмбеддингов.

**Что делает:**
- Объединяет заголовок, аннотацию, ключевые слова и основной текст
- Нормализует каждую часть
- Разделяет части двойными переносами строк

---

#### Функция `build_clean_text(text: str) -> str`

Строит очищенный текст без формул и специальных символов.

**Что делает:**
- Удаляет греческие символы, латиницу, цифры
- Удаляет математические символы и скобки
- Очищает пунктуацию
- Возвращает чистый русский текст

---

### parser_part2.py

#### Класс `TOCExtractor`

Класс для извлечения тематических разделов из содержания PDF.

##### `extract_toc_lines(pdf_path: Path, max_pages: int = 30) -> list`

Извлекает строки из раздела «Содержание» PDF.

**Параметры:**
- `pdf_path` (Path): Путь к PDF файлу
- `max_pages` (int): Максимальное количество страниц для поиска (по умолчанию 30)

**Возвращает:**
- Список нормализованных строк из содержания

**Что делает:**
- Открывает PDF и последовательно читает страницы
- Находит заголовок «Содержание» (русский)
- Собирает строки до начала статей (маркер УДК) или до маркера «Content»
- Пропускает служебную информацию (название журнала)

---

##### `parse_toc_entries(pdf_path: Path) -> list`

Парсит записи из содержания PDF в структурированный формат.

**Возвращает:**
- Список словарей с полями:
  - `topic`: тема раздела
  - `toc_title`: заголовок статьи из содержания
  - `toc_page`: номер страницы

**Что делает:**
1. Извлекает строки содержания
2. Определяет заголовки тем (ключевые слова + заглавные буквы)
3. Собирает многострочные заголовки тем
4. Извлекает названия статей и номера страниц
5. Сопоставляет статьи с их тематическими разделами

---

##### `sanitize_toc_topics(toc_entries) -> tuple`

Очищает и валидирует темы из содержания.

**Возвращает:**
- `(очищенные_записи, флаг_no_theme_mode)`

**Что делает:**
- Удаляет темы, похожие на заголовки статей (similarity >= 0.82)
- Удаляет некорректные темы (длинные, с цифрами, с инициалами авторов)
- Удаляет уникальные длинные темы
- Определяет режим «без тем» (если темы не выражены или их слишком много)

---

### parser_part3.py

#### Класс `TopicMatcher`

Класс для сопоставления статей с темами из содержания.

##### `title_score(a: str, b: str) -> float`

Вычисляет схожесть двух заголовков.

**Возвращает:**
- Оценка схожести от 0.0 до 1.0 (комбинация пересечения токенов и SequenceMatcher)

---

##### `assign_topics_from_toc(rows, toc_entries, no_theme_mode) -> list`

Назначает темы статьям на основе содержания.

**Параметры:**
- `rows` (list): Список статей с полями `title`, `pdf_page`
- `toc_entries` (list): Записи из содержания
- `no_theme_mode` (bool): Режим без тем

**Возвращает:**
- Список статей с добавленными полями `topic`, `topic_match_score`, `topic_match_toc_title`

**Что делает:**
1. Для каждой статьи ищет лучшее совпадение в содержании (локальный поиск ±22 записи)
2. Если локальный поиск не дал результата (score < 0.34), делает глобальный поиск
3. Учитывает близость номеров страниц как бонус к score
4. Если тема не найдена, определяет её по номеру страницы (через точки смены тем)
5. Назначает `Тема не указана в содержании` или `Тема не определена` при необходимости

---

#### Класс `IMTArticleParser`

Главный класс для парсинга статей из PDF файлов IMT.

##### `extract_pages_with_numbers(pdf_path: Path) -> list`

Извлекает текст из PDF постранично с номерами страниц.

**Возвращает:**
- Список кортежей `(номер_страницы, текст)`

**Что делает:**
- Открывает PDF через pdfplumber
- Для каждой страницы обрезает верх и низ (45px) для удаления колонтитулов
- Извлекает текст (сначала обычным способом, потом с layout=True если не удалось)
- Возвращает список страниц с их номерами

---

##### `get_title(chunk: str) -> str`

Извлекает заголовок статьи из текстового блока.

**Что делает:**
- Ищет текст после маркера «УДК»
- Пропускает мусорные строки и строки с авторами
- Собирает заголовок (2-4 строки)

---

##### `get_authors(chunk: str) -> str`

Извлекает авторов статьи.

**Возвращает:**
- Строка с авторами через запятую (формат: Фамилия И.О.)

**Что делает:**
- Ищет строки с ФИО (заглавная буква + строчные + пробел + инициалы)
- Собирает всех авторов из строки

---

##### `extract_annotation_and_keywords(chunk: str) -> tuple`

Извлекает аннотацию и ключевые слова.

**Возвращает:**
- Кортеж `(аннотация, ключевые_слова)`

**Что делает:**
- Ищет блок «Аннотация» до маркеров «Ключевые слова», «Введение» и др.
- Ищет блок «Ключевые слова» до маркеров «Цитирование», «Введение», «СПИСОК» и др.
- Нормализует извлеченный текст

---

##### `extract_main_text(chunk: str) -> str`

Извлекает основной текст статьи.

**Что делает:**
- Ищет начало статьи («Введение» или «1. Введение»)
- Обрезает список литературы («СПИСОК ЛИТЕРАТУРЫ» и др.)
- Очищает текст через `TextProcessor.clean_main_text()`

---

##### `parse_articles_from_pdf(pages_with_nums, filename: str) -> list`

Парсит статьи из страниц PDF.

**Что делает:**
1. Объединяет все страницы, маркируя их `__PAGE_X__`
2. Разбивает по маркеру УДК на отдельные статьи
3. Для каждой статьи:
   - Извлекает номер страницы, УДК, заголовок, авторов
   - Извлекает аннотацию и ключевые слова
   - Извлекает основной текст
   - Токенизирует для LDA
   - Строит полный текст для эмбеддингов
4. Фильтрует статьи (должны быть обязательные поля, текст >= 120 слов)

---

##### `parse_folder(pdf_folder: Path, output_csv: Path) -> pd.DataFrame`

Парсит все PDF файлы в папке и сохраняет результат в CSV.

**Что делает:**
1. Находит все PDF файлы в папке
2. Для каждого PDF:
   - Извлекает содержание и темы
   - Извлекает страницы с текстом
   - Парсит статьи
   - Сопоставляет с темами из содержания
3. Объединяет все статьи в DataFrame
4. Удаляет служебные колонки
5. Сохраняет в CSV

**Пример вывода:**
```
Parsing IMT PDFs: 100%|████████| 45/45 [05:30<00:00, 7.33s/it]
✓ Парсинг завершен: 312 статей
✓ Сохранено в: project_data/dataset_IMT.csv
✓ Уникальных УДК: 28
✓ Уникальных тем: 15
```

---

### Функция `parse_imt_folder(pdf_folder: str, output_csv: str) -> pd.DataFrame`

Удобная функция для парсинга папки с PDF.

**Параметры:**
- `pdf_folder` (str): Путь к папке с PDF
- `output_csv` (str): Путь для сохранения CSV

**Пример использования:**
```python
from backend.stages.parser import parse_imt_folder

df = parse_imt_folder(
    pdf_folder="project_data/pdfs/imt",
    output_csv="project_data/dataset_IMT.csv"
)
print(f"Спарсено статей: {len(df)}")
```

## Зависимости

- `re`: Регулярные выражения
- `pathlib`: Работа с путями
- `difflib`: Вычисление схожести строк (SequenceMatcher)
- `pandas`: Работа с табличными данными
- `pdfplumber`: Извлечение текста из PDF
- `tqdm`: Прогресс-бар
- `pymorphy3`: Лемматизация текста
- `nltk`: Стоп-слова

---

## Примечания

- Парсер обрабатывает только статьи, где заполнены заголовок, аннотация и ключевые слова
- Минимальный размер основного текста статьи — 120 слов
- Страницы PDF обрезаются сверху и снизу на 45px для удаления колонтитулов
- Список литературы автоматически отсекается
- Темы определяются двумя способами: по содержанию и по номеру страницы
- Если темы в содержании некорректны, включается режим «без тем»
